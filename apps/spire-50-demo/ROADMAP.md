> **한 줄 목표**: 층마다 만나는 인물이 아군일지 적군일지 달라지는 탑다운 액션 로그라이크를, 5층 보스까지 완주할 수 있는 웹 데모로 만든다.

> **패키지/폴더명**: `apps/spire-50-demo`
> **기술 기반**: React 18, Phaser 3.90, Zustand, Vite 6, TypeScript strict, Zod, Howler.js, pnpm/Turborepo
> **작성일**: 2026-08-20
> **상태**: 계획 수립 완료, 구현 대기

## 1. 제품 방향과 범위

### 1.1 데모 판타지

- 플레이어는 50층짜리 거대 탑의 초보 도전자다.
- 데모는 **1~5층**을 실제 공략 가능하게 만들고, 데이터 구조와 타이틀의 층수 표시는 최종 50층 확장을 전제로 한다.
- 첫 플레이의 감정 곡선은 `압도적인 탑 → 무기 선택 → 안전한 휴식처 → 첫 스킬 획득 → 전투 승리 → 전리품 회수 → 상점/귀환` 순서다.
- 각 층에는 1명 이상의 방랑자가 시드에 따라 등장하며, 관계 판정 결과에 따라 플레이어와 협력하거나 몬스터 편에 선다.
- 전체 런의 결말은 5층 보스 처치이며, 성공 조건에는 랜덤으로 합류한 동료가 전투에 실제로 기여한 기록이 포함된다.
- 참조작의 핵심 감각인 빠른 이동, 커서 지향 공격, 화면을 크게 쓰는 공격 이펙트, 짧은 전투 후 즉시 보상을 참고하되 명칭·캐릭터·맵·UI 장식·효과음은 독자적으로 만든다.

### 1.2 이번 데모에 포함

- 타이틀, 현재 도달 층수, 새 게임 버튼.
- 기본 캐릭터 1명과 무기 5종 선택 화면.
- Lv.1 초보자 상태와 선택한 무기 1개를 보존하는 런 상태.
- 탑 휴식처, 1~5층 공략 구역, 아이템 상점의 3개 맵 유형과 층별 레이아웃.
- 탑 관리자와의 최초 진입 대화 및 첫 목표 안내.
- WASD 이동, 커서 지향 기본 공격, 숫자 `1` 스킬, `Z` 회수, 포탈 상호작용.
- 몬스터, 체력바, 피격/사망, 돈·아이템 드롭과 회수.
- 층별 방랑자 등장, 아군/적군 관계 판정, 아군 추종·공격 AI, 적대 방랑자 전투.
- 체력/마력 HUD, 빠른 데모용 자연 회복, 기본 사운드와 화면 피드백.
- `localStorage`에 최고 도달 층, 골드, 선택 무기, 루트 시드, 스냅샷과 압축된 명령 이력 저장.

### 1.3 이번 데모에서 제외

- 6~50층의 실제 스테이지와 추가 보스.
- 온라인 계정, 서버 저장, 멀티플레이, 결제.
- 완성형 장비 인벤토리, 제작, 퀘스트, 다중 캐릭터 해금.
- 무기별 완전한 스킬트리. 데모에서는 무기마다 첫 액티브 스킬 1개와 잠긴 후속 노드 미리보기만 제공한다.
- 모바일/게임패드 조작. 입력 추상화는 유지하되 데스크톱 키보드·마우스를 우선한다.

### 1.4 원작·참조물 사용 원칙

- `[세피리아]`는 전투 템포, 드롭 회수, HUD 정보 구조를 이해하는 **레퍼런스**로만 사용한다.
- `타이틀.jpg`의 실제 게임명·배경·폰트를 복제하지 않는다. 좌측 타이틀/세로 메뉴 구성, 손글씨 느낌, 깊이감 있는 환경 연출만 참고해 거대한 탑 중심의 독자 화면을 만든다.
- `캐릭1.jpg`는 사용자가 지정한 초기 캐릭터의 프로토타입 초상으로 사용하되, 배포 전 사용 권한을 확인한다. 실제 플레이용 탑다운 스프라이트와 애니메이션은 별도 제작한다.
- 제공 이미지의 제3자 로고, 원작 캐릭터, 맵 타일, UI를 게임 빌드에 그대로 포함하지 않는다.

### 1.5 확정된 에셋 조달 원칙

- 1순위는 [Kenney 2D 에셋](https://kenney.nl/assets/category:2D/page:4)이다. [공식 지원 안내](https://kenney.nl/support)상 게임 에셋은 CC0이며 출처 표기는 필수가 아니지만, 내부 `assets/README.md`에는 패키지명·원본 URL·다운로드일을 기록한다.
- [AetherAI 무료 에셋](https://www.aetherforgeai.com/ko/free-assets)은 후보로 사용하되, 무료 에셋 페이지의 일괄 라이선스를 확인하지 못했으므로 **개별 다운로드 페이지/동봉 라이선스가 상업적 웹 배포를 허용할 때만** 포함한다.
- 캐릭터와 방랑자는 GPT와 Gemini에서 각각 후보를 생성해 가독성·프레임 일관성·독창성 기준으로 비교하고, 선택한 결과를 AetherAI 등의 스프라이트 도구로 8방향 시트화한다.
- 생성형 에셋 장부에는 모델, 프롬프트, 참조 이미지, 생성일, 후처리, 사용 권한 확인 상태를 기록한다.
- 생성형 결과가 특정 원작 캐릭터·화풍·로고와 지나치게 유사하면 폐기하고 재생성한다.

## 3. 우선순위와 마일스톤

### P1 — 핵심 수직 슬라이스 (최우선 플레이 가능 빌드)

목표: 임시 자산을 사용하더라도 첫 10분 안에 1층의 시작부터 보상까지 한 사이클이 완주되고, 방랑자 관계 시스템이 한 번 발생한다.

#### P1.1 타이틀과 선택

- [ ] 타워 전경 배경, 독자 타이틀 로고, 최고 도달 층/목표 50층 표시.
- [ ] `게임 시작` 버튼의 hover, 클릭, 키보드 포커스 상태.
- [ ] 캐릭터 카드 1개만 해금; 나머지 슬롯은 `봉인됨`으로 비활성 미리보기.
- [ ] 장검/단검/방패/활/지팡이 중 정확히 하나만 선택 가능.
- [ ] 선택 요약에 `Lv.1 초보자`, 기본 능력치, 공격 방식, 첫 스킬 표시.
- [ ] 선택 완료 전 출발 버튼 비활성, 완료 후 휴식처로 전환.

#### P1.2 휴식처와 대화

- [ ] 1층 휴식처에 플레이어, 탑 관리자, 공략 포탈, 상점 포탈 배치.
- [ ] 최초 진입 시 이동을 잠그고 관리자 대화를 자동 시작.
- [ ] 대화 내용: 탑의 목적, 50층 목표, 현재 1층, 조작법, 첫 임무.
- [ ] 첫 목표 한 줄을 HUD에 고정: `선택한 무기의 첫 스킬을 획득하라`.
- [ ] 대화 종료 시 선택 무기에 대응하는 첫 스킬 해금 및 숫자 `1` 슬롯 점등.

#### P1.3 이동과 전투

- [ ] WASD 8방향 이동, 대각선 속도 정규화, 벽/장애물 충돌.
- [ ] 마우스 커서 방향을 향하는 캐릭터와 공격 방향 표시.
- [ ] 우클릭 기본 공격: 무기별 공격 판정, 쿨다운, 모션/잔상, 타격 정지.
- [ ] 숫자 `1` 스킬: 마나 소모, 쿨다운, 커서 지향, 범위/투사체 판정.
- [ ] 최소 몬스터 2종: 근접 추적형과 원거리/돌진형 중 하나.

## 4. 화면별 상세 요구사항

### 4.1 타이틀 화면

- 배경: 화면 하단에서 시작해 구름 너머로 끝이 보이지 않는 탑. 느린 구름과 작은 새/부유 석편으로 크기 대비를 만든다.
- 좌측: 독자적인 붓글씨 계열 로고 `제50첨탑`, 부제 `THE FIFTIETH SPIRE`.
- 로고 아래: `현재 최고 1F`와 `최종 목표 50F`.
- 메뉴: `게임 시작`을 주 CTA로 두고, 데모에서는 `설정`만 보조 제공. 저장 불러오기는 실제 저장 기능이 생길 때까지 노출하지 않는다.
- 버튼 피드백: 기본/hover/pressed/focus/disabled 상태를 모두 제공한다.

### 4.2 캐릭터·무기 선택

- 좌측 45%: `캐릭1.jpg` 기반 초상, 이름(임시: `에른`), `Lv.1 초보자`.
- 우측 상단: 무기 5종 탭. 한 번에 하나만 활성화하며 선택 무기를 캐릭터 실루엣/아이콘에 반영.
- 우측 중앙: 공격력/속도/범위/난이도를 텍스트와 막대로 비교.
- 우측 하단: 첫 스킬 설명과 출발 버튼.
- 접근성: 색상뿐 아니라 테두리, 아이콘, `선택됨` 라벨로 현재 선택을 전달.

### 4.3 게임 플레이 HUD

- 좌상단: 캐릭터 초상, Lv.1, HP(빨강), MP(청록), 현재 골드.
- 상단 중앙: `탑 {현재 층}층 · 휴식처/공략 구역/상점`과 현재 목표 한 줄.
- 우상단: 간단한 미니맵 또는 현재 구역/포탈 방향 표시. P1에서는 텍스트 방향표도 허용.
- 우하단: 우클릭 기본 공격, `1` 스킬 슬롯, 쿨다운 원형 마스크, 마나 비용.
- 캐릭터/몬스터 주변: 적 체력바는 각 몬스터 하단, 대미지 숫자는 피격 지점에서 짧게 상승 후 소멸.
- 중앙 하단: `Z 회수`, `W 포탈 이동`, 관리자 대화 등 상황별 프롬프트.

### 4.4 대화 UI

- 화면 하단 약 30% 높이의 반투명 어두운 패널.
- 관리자와 플레이어 초상을 대사 화자에 따라 강조하고, 이름표와 본문을 분리.
- 클릭/`Space`로 다음 대사, 길게 누르지 않아도 한 번에 한 단계만 진행.
- 대화 중 공격과 이동은 잠그되 설정 메뉴는 열 수 있다.
- 마지막 대사 종료 시 목표 토스트와 스킬 해금 연출이 연속으로 나온다.

```text
    │   ├── game-store.ts
    │   └── event-queue.ts
    ├── audio/
    │   └── audio-manager.ts
    └── persistence/
        ├── save-schema.ts
        └── save-repository.ts
```

### 6.2 상태 흐름

```text
React Title
  → React Select(character=default, weapon=one of five)
    → Phaser Rest(firstVisit dialogue → unlock skill)
      → for floor 1..5
        → Phaser Battle(seed → layout + wanderer role + enemies)
        → React FloorResult(loot + ally contribution)
        → Phaser Rest ↔ React Shop
      → React RunResult(floor 5 boss cleared with ally contribution)
```

React는 타이틀·선택·대화·상점·결산처럼 문서형 UI를 담당한다. Phaser는 월드, 스프라이트, 카메라, 파티클을 담당한다. 두 계층은 순수 엔진 명령과 Zustand 스냅샷/연출 이벤트 큐로만 통신한다.

### 6.3 핵심 데이터 모델

- `RunState`: `saveVersion`, 루트 시드, 캐릭터/무기, 레벨, HP/MP, 골드, 인벤토리, 현재/최고 층, 목표, 첫 방문 플래그, 방랑자 기록.
- `GameCommand`: 이동 의도, 기본 공격, 스킬 사용, 회수, 포탈, 대화 진행, 구매 등 규칙 엔진에 전달되는 직렬화 가능한 입력.
- `GameEvent`: 피격, 사망, 드롭, 관계 공개, 스킬 해금, 포탈 활성 등 React/Phaser/Howler가 소비하는 일회성 연출 이벤트.
- `WeaponDefinition`: 기본 공격 수치/판정/애니메이션 키, 첫 스킬 ID, 아이콘, 설명.
- `SkillDefinition`: 피해 배율, 마나, 쿨다운, 범위 형태, 투사체/근접 여부, 이펙트 키.
- `EnemyDefinition`: 최대 HP, 이동/공격 방식, 피해량, 드롭 테이블, 체력바 오프셋.
- `WandererDefinition`: 후보 ID, 전투 키트, 등장 가능 층, 관계 가중치, 아군/적군 AI 프로필.
- `WandererEncounter`: 층, 후보, 관계, 관계 보정 여부, 생존, 피해 기여량.
- `FloorDefinition`: 레이아웃 풀, 웨이브, 보상 계수, 방랑자 수 범위, 클리어/보스 조건.
- `PortalDefinition`: 출발 구역, 도착 구역, 활성 조건, 상호작용 키.
- `DialogueSequence`: 화자, 초상, 본문, 종료 후 이벤트.

### 6.4 구현 원칙

- 순수 TypeScript 엔진이 상태 전이와 판정의 유일한 권위다. Phaser는 엔진 스냅샷을 표시하고 입력 명령을 전달한다.
- Zustand는 최신 엔진 스냅샷과 연출 이벤트 큐의 단일 저장소다. React/Phaser는 구독만 하고 임의 상태를 만들지 않는다.
- Phaser 오브젝트 수명은 씬이 관리하고, 전투/경제/관계 수치 계산은 순수 함수로 둔다.
- 씬 사이 전역 이벤트 리스너는 종료 시 반드시 해제해 중복 공격/대화 진행을 막는다.
- 무기별 분기문을 퍼뜨리지 않고 `WeaponDefinition`과 전략 함수로 판정을 교체한다.
- 밸런스 수치는 한 파일에서 조정하고 코드에 매직 넘버를 넣지 않는다.
- 게임 랜덤은 `Math.random()` 대신 `@game/core`의 RNG를 루트 시드에서 용도별 서브 스트림으로 파생해 사용한다. 파티클 RNG는 드롭/관계 RNG를 소비하지 않는다.
- Zod가 밸런스 데이터와 저장 데이터를 시작 시 검증하며, 손상 저장은 백업 키로 이동한 뒤 안전한 새 런을 제안한다.
- 저장은 `localStorage` 단일 슬롯으로 제한하고 `saveVersion + rootSeed + snapshot + commandHistory`를 기록한다. 명령 이력은 층 종료 시 스냅샷으로 압축하고 최근 500개까지만 유지한다.
- Howler.js는 첫 사용자 입력 후 오디오 컨텍스트를 열고, 동일 SFX에 작은 피치/볼륨 변형만 적용한다.
- UI와 게임 텍스트는 한국어 단일 언어로 작성하며 P2까지 i18n 프레임워크를 도입하지 않는다.

## 8. 품질 기준과 Definition of Done

### 기능 완성

- [ ] 위 FR-01~FR-18이 우선순위 단계에 맞게 모두 동작한다.
- [ ] 타이틀에서 5층 보스 결산까지 강제 새로고침 없이 진행된다.
- [ ] 플레이어 사망, 재도전, 구역 왕복 후에도 입력/이벤트가 중복되지 않는다.

### 성능과 호환성

- [ ] 데스크톱 Chrome/Edge 최신 버전에서 목표 60FPS, 전투 중 최소 50FPS.
- [ ] 첫 화면 로딩 5초 이내(일반 광대역, 개발 서버 제외), 초기 다운로드 크기 기록.
- [ ] 캔버스는 16:9 비율을 유지하고 최소 960×540 뷰포트에서 UI가 잘리지 않는다.
- [ ] 탭 비활성/재활성 후 눌린 키 상태가 남지 않는다.

### 코드 품질

- [ ] TypeScript strict 오류 0개.
- [ ] 루트 빌드/타입 검사/테스트 성공.
- [ ] 순수 전투·드롭·회복 로직의 핵심 경계값 테스트 포함.
- [ ] 같은 시드+명령 이력의 최종 스냅샷 해시가 100회 재생에서 동일하다.
- [ ] cosmetic RNG 소비량을 바꿔도 관계·드롭 결과가 바뀌지 않는다.
- [ ] 자산 출처와 라이선스/사용 권한 상태가 파일 단위로 기록된다.
